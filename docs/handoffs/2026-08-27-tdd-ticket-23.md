- **The default N (31250) is not this column's efficiency.** Every peak in every run implies 14–27 k plates.
- **The combination rule barely matters on this data.** Arithmetic, harmonic and geometric means of the two implied N agree within 0.5%; least squares in absolute σ differs by 2–5%; run-1-only and run-2-only bracket them. Research §3.2 derives which is maximum-likelihood under which error model; **§3.3 recommends the geometric mean** (least squares in ln W — the estimator under which §5.4's G convention was chosen). Take it.
- **Held-out Rs with fitted N** (measured Rs from measured tR and W½):

  | pair | tG = 25 predicted / measured | tG = 60 predicted / measured |
  |---|---|---|
  | Unknown-1 → 2 | 32.3 / 33.8 = **0.955** (−1.5 abs) | 34.1 / 36.5 = **0.935** (−2.4 abs) |
  | Unknown-2 → 3 | 96.3 / 100.7 = **0.956** (−4.5 abs) | 104.3 / 115.9 = **0.900** (−11.6 abs) |

  With the default N those ratios were 1.390 / 1.254 (tG 25) and 1.360 / 1.181 (tG 60). So: **the ticket's "~1.5–11.7%" is a units slip — it is 1.5–11.6 absolute Rs units**, i.e. −4.4% to −10.0%, and the sign flips from optimistic to slightly pessimistic. The (1.1, 1.6) guard fails with fitted N exactly as designed (no ratio is even above 1.0).
- **The tG = 25 comparison is inside its own noise.** `run3.csv` records W½ to two decimals (0.05 / 0.05 / 0.04), so the *measured* Rs there is uncertain by −9.1..+11.1% (pair 1→2) and −10.0..+12.5% (pair 2→3). The fitted-N ratios of 0.955 / 0.956 sit inside that band; at tG = 60 (three decimals, ±0.5%) the −6.5% / −10.0% is real.
- **Rs ± 0.3 stays unmet** (criterion 2's honest answer): the absolute errors are 1.5–11.6 Rs units at Rs 30–116, and research-doc §6's obstacle 2 (the sample never enters Rs ≈ 1–3) is now the only obstacle. In-sample (runs 1–2) with fitted N the Rs ratios are 0.990 / 0.974 and 1.011 / 1.027 — one N per compound cannot be exact in both runs.
- **Per-compound N is justified, not just convenient** (research §2): the solute diffusion coefficient enters the C term, extra-column variance scales as 1/(1+k_e)² so every gradient peak pays it and steeper gradients pay more, and USP ⟨621⟩ itself says "the plate number varies with the component". Unknown-3's N is 1.6× the others' with the *narrowest* peaks, which extra-column dispersion cannot explain — exactly the case one global N misrepresents.
- **What is fitted is not a pharmacopoeial plate number.** It is the apparent, instrument-inclusive, G-conditional efficiency that reproduces the gradient width (research §1.4, §2.2, §2.3). Residual G error is absorbed into N (N ∝ G², so a 5% G error is 10% of N) — harmless as long as the same G convention fits and predicts. Say so in the docstring. USP's half-height constant is **5.54**, 0.093% below the exact 8 ln 2 = 5.5452 the engine uses; never mix them.
- **The 2.303 slip now enters N squared**: a slipped G or k_e in the inverse is a 20–30% N error. The existing calibration tests still guard G; the new inverse must share `peak_width`'s code path, not re-state the formula.
- **DryLab's route is confirmed from Molnár (2002) read in full** (research §1.1): different plate numbers per chromatogram region (his §9), then "measured peak widths as input data" (his §16). Whether DryLab derives N per peak or splines it is *not* documented anywhere reachable; academic implementations use one column N. The §5.1 mis-citation (§16 for the "front/middle/final third" sentence) is fixed in this branch's first commit.
- **No primary source documents a precedence rule** for "global N and per-peak widths both present" (research §5). Measured-first is this project's own convention by analogy with SPEC §4's t0 rule — state it as such in SPEC.

## Design recommendations — the session's call

Reuse, don't rebuild: `peak_width` already branches on regime and applies G; `fit_peak` already has the peak, method and both runs; `Peak.w_half_run1` / `w_half_run2` already exist; `RetentionResult.regime` tells you which regime a scouting run put the band in. Invoke `codebase-design` only if the seam below turns out to be architectural.

1. **The inverse has one home.** `plate_count_from_width(params, method, gradient, w_half)` = `(peak_width(params, method, gradient, plate_count=1.0).w_half / w_half) ** 2`. σ ∝ 1/√N exactly, so this is the algebraic inverse and it inherits the regime branch and G for free. Do not write G·t0·(1+k_e)/√N a second time.
2. **The fit is per peak, from that peak's scouting widths.** Something like `FittedPlateCount(plate_count, implied_run1, implied_run2, low_confidence)` with `ratio` as a property; `plate_count` is the geometric mean of the implied values present. Populate it from `fit_peak` as `FitResult.plate_count: FittedPlateCount | None` (`None` when the peak carries no width) — the fit is "everything the two runs say about this peak", and `fit.py` importing `width.py` creates no cycle.
3. **Regime rule** (research §4.2–4.3): a hold-regime width is the cleanest N there is (the inverse reduces exactly to USP's 8 ln 2·(tR/W½)²); a **post-gradient** width is neither compressed nor isocratic — do not use it when the peak has another width; if it is the only width, use it and stamp `low_confidence`. Warnings over blocks: never refuse a width. The lab peaks are all in the gradient regime in every run, so this rule is tested synthetically.
4. **One width is enough** — N from that width, `ratio` is `None`. Two widths give the ratio as a diagnostic number; **no threshold in this ticket** (that is #20's; research §6 item 3 suggests ~±10% as the eventual line — note Unknown-3 already sits at 1.16).
5. **Provenance, three-way.** Replace `PeakWidth.plate_count_is_default: bool` with `plate_count_source: Literal["default", "supplied", "fitted"]` (research §6 item 2, mirroring `t0_source`). `peak_width(..., plate_count: float | FittedPlateCount | None)` — a float is "supplied", the fit object is "fitted", `None` is "default". SPEC §6 diagnostic 5 and the #17 handoff name the bool; update the SPEC mention in the amendment (the banner caveats "default" only).
6. **Precedence, measured-first:** fitted (per peak) > global knob > geometry default. `resolution_table(params, method, gradient, *, names=None, plate_count=None, plate_counts=None)` — `plate_counts` is per peak (`FittedPlateCount | None` per entry, `None` falling through to the global `plate_count`, which falls through to the default). A third parallel list is the minimal change and matches the `fit_peaks` positional style the #17 review accepted; if it reads badly, bundling `(params, name, plate_count)` into one input type is the alternative — but that is a wider API change than the ticket needs.
7. **Do not**: touch `retention.gradient_steepness` (b_e's single home); change the session schema (§8 is inputs-only; N fitted is a result and is never serialized — `test_file_holds_no_fitted_results` should gain a fitted-N field name); add a `k_e`/Δφ_e diagnostic (that is the diagnostics ticket); round any constant.
