## Facts a fresh agent should not re-derive (pre-build validation, 2026-08-26)

The specified algorithm was implemented as a throwaway script and validated against the lab data before any production code. Use these as characterization fixtures (they are conversation-era numbers; the measured values live in `validation/`, the ticket-#8 comments hold the summary):

- Method constants: t0 = 0.6 min, tD = 0.9375 min (0.375 mL @ 0.4 mL/min), t_init = 0.5 min, φ0 = 0.05, φf = 0.95 (Δφ = 0.90).
- Retention equation used: tR = τ + t0 + (t0/b_e)·ln[b_e·(k0 − τ/t0) + 1], τ = tD + t_init, b_e = t0·Δφ·S_e/tG.
- Fit from runs at tG = 15/45 gave, per peak (Unknown-1/2/3): S(base-10) ≈ 5.08 / 4.99 / 5.18; log10 k0 ≈ 2.76 / 3.24 / 4.76.
- Blind predictions vs measured: tG = 25 → 13.861/16.729/24.383 vs 13.787/16.658/24.358 (avg 0.35%); tG = 60 → 25.480/32.236/50.774 vs 25.587/32.320/50.821 (avg 0.26%). Signed bias flips between the two conditions (mild LSS curvature — expected, not a bug).
- A correct engine must reproduce ~these numbers from `validation/` inputs. If it doesn't, suspect the log-base convention, a dropped τ term, or t0 handling first.
